# Algebra Practice Agent

**[Отчёт: сравнение фреймворков и проверка агента](HOMEWORK.md)**

Пример LangChain с собственным инструментом `get_practice_task` для
преподавателя алгебры. Инструмент возвращает проверенное условие по теме
и сложности, не передавая агенту ключ ответа.

## Запуск

Python 3.11+.

```bash
python -m venv .venv
# Windows
.venv\Scripts\activate
pip install -r requirements.txt
```

Скопировать `.env.example` в `.env`, заполнить настройки совместимого API.

```bash
python agent.py
python agent.py --demo
python -m unittest -v
```

В интерактивном режиме выход — `/exit`.
`--demo` делает реальные платные вызовы настроенной модели, проверяет
факт обращения к инструменту и сохраняет сообщения в `results/demo.json`.
Ключи в результаты не записываются. `requirements.txt` фиксирует прямые
зависимости; полный проверенный набор — `requirements-lock.txt`.

## Возможности

Темы: уравнения (`equations`), скобки (`brackets`).
Сложности: `easy`, `medium`, `hard`. Всего 6 авторских упражнений.
Для неизвестной комбинации инструмент возвращает ошибку и доступные варианты.
Модель выбирает аргументы инструмента, получает условие и ждёт попытку.
Ответы содержатся в исходном учебном наборе, но tool их не возвращает.
Это не система безопасного экзамена: сама модель может решить условие.

`create_agent` использует `InMemorySaver` и `thread_id`: в пределах процесса
агент помнит тему уточнения. После завершения процесса память теряется.
Постоянная память первого ДЗ и Pinecone второго ДЗ этим примером не заменены.
Telegram-бот не меняется и агент в него пока не встроен.

Проверка 03.11.2026 на gpt-6-luna: реальный вызов инструмента для easy,
затем medium по уточнению без повторного указания темы; оба условия совпали
с набором. Три локальных теста проверяют выдачу условия без ключа ответа,
смену уровня и отсутствие выдуманного задания для неизвестной темы.
