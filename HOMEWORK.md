# Отчёт по заданию VPg03 — выбор фреймворка для ИИ-преподавателя

## Задача проекта

Разрабатывается преподаватель для учениц 7 класса: объяснение темы,
практика, самостоятельная проверка и разбор ошибок. Нужны отдельный
прогресс каждой ученицы, продолжение занятия с нужного шага и ответы
по проверенным учебным материалам. Уже реализованы сохранение диалога
в SQLite и отдельный эксперимент смыслового поиска в Pinecone.

Для сравнения выбраны LangChain, LlamaIndex и Haystack.

## LangChain и LangGraph

LangChain предоставляет интерфейсы моделей, агентов и инструментов.
Агент может выбрать функцию, передать ей аргументы и использовать результат.
LangGraph позволяет явно задавать процесс через состояние, узлы и переходы.
Checkpointer сохраняет состояние конкретного диалога, а store — данные,
которые должны использоваться между диалогами. Для устойчивого хранения
нужно выбрать постоянное хранилище, а не ограничиваться памятью процесса.

**Применение:** этапы «объяснение → попытка → подсказка → повторная попытка
→ проверка»; инструменты подбора упражнений и обращения к прогрессу ученицы.
Например, после неверного ответа процесс должен вернуться к объяснению
конкретного правила, а не перейти к следующей теме.

**Преимущество для проекта:** возможность явно управлять ходом занятия
и разделять состояние разных диалогов.

**Ограничение:** педагогические переходы и критерии освоения придётся
спроектировать самостоятельно. Наличие памяти ещё не означает правильную
оценку знаний. Для небольшого бота такой уровень управления может быть избыточен.

Источники: [LangChain Quickstart](https://docs.langchain.com/oss/python/langchain/quickstart),
[LangGraph Persistence](https://docs.langchain.com/oss/python/langgraph/persistence).

## LlamaIndex

LlamaIndex предоставляет средства загрузки, разбиения, индексации
и поиска по данным. Документы представлены как Documents, их фрагменты —
как Nodes. Retrieval выбирает подходящие фрагменты, а генерация использует
их для ответа. Во фреймворке также есть агенты и workflows: он не ограничен
только поиском по файлам.

**Применение:** библиотека проверенных учебных материалов с привязкой
к предмету, теме и источнику. По вопросу ученицы система находит правило
и связанные примеры, которые преподаватель использует при объяснении.

**Преимущество для проекта:** готовые средства работы с документами
и поиском по собственным данным.

**Ограничение:** организация RAG не гарантирует, что формулы и рисунки
правильно извлечены. Подготовку учебников, проверку условий и сохранение
номеров упражнений нужно контролировать отдельно. Не следует считать,
что обычный парсер фреймворка автоматически решает эти задачи.

Источник: [LlamaIndex — Introduction to RAG](https://developers.llamaindex.ai/python/framework/understanding/rag/).

## Haystack

Haystack строит обработку данных из компонентов, соединённых в пайплайны.
Можно явно разделить индексацию, поиск и генерацию. Также поддерживаются
агенты, инструменты, document stores и интеграции.

**Применение:** цепочка «запрос ученицы → эмбеддинг → поиск в Pinecone
→ отбор фрагментов → объяснение по найденным материалам». Отдельный
пайплайн обрабатывает новые учебные документы и сохраняет их в базе.

**Преимущество для проекта:** явные границы этапов позволяют проверять,
где возникла проблема: при чтении документа, поиске или генерации ответа.

**Ограничение:** компоненты и переходы требуют настройки. Учебная логика,
учёт подсказок и оценка освоения не появляются автоматически.

Источники: [Haystack — Introduction](https://docs.haystack.deepset.ai/),
[Haystack — Pipelines](https://docs.haystack.deepset.ai/docs/pipelines).

## Сравнение и выбор

| Потребность преподавателя | Что стоит рассмотреть |
|---|---|
| Управление этапами занятия и состоянием диалога | LangChain вместе с LangGraph |
| Подготовка и поиск по большой библиотеке материалов | LlamaIndex |
| Явные пайплайны индексации, поиска и генерации | Haystack |

Это акценты применения, а не взаимоисключающие возможности: все три
фреймворка способны участвовать в RAG и агентных приложениях.

Для следующих практических этапов выбран Haystack: его пайплайны подходят
для разделения работы с учебными данными и прямо используются в дальнейших
заданиях. LangChain выбран для небольшого агентного эксперимента в этом
задании. LangGraph остаётся кандидатом для более сложного управления
учебными этапами, LlamaIndex — альтернативой при расширении библиотеки.
Подключать все три одновременно сейчас не требуется.

## Дополнительная часть: агент с собственным инструментом

Создан агент LangChain через `create_agent`. Собственный инструмент
`get_practice_task(topic, difficulty)` выбирает упражнение из набора
6 авторских задач: две темы и три уровня сложности. Результат содержит
ID и точное условие. Ключ ответа инструмент агенту не возвращает.
Для неизвестного сочетания возвращаются сообщение об ошибке и доступные
параметры вместо выдуманного задания.

Память примера — `InMemorySaver` с отдельным `thread_id`. Она сохраняет
контекст только в пределах процесса и не заменяет постоянную SQLite-память.

### Реальный запрос 1

Запрос: «Дай простое упражнение на линейные уравнения».

Модель вызвала:

```json
{"name": "get_practice_task", "args": {"difficulty": "easy", "topic": "equations"}}
```

Инструмент вернул `eq-e1`: «Реши уравнение x + 3 = 10».
Агент показал условие и попросил прислать попытку, не раскрывая решение.

### Реальный запрос 2

Запрос: «Дай сложнее по той же теме».

Модель вызвала:

```json
{"name": "get_practice_task", "args": {"difficulty": "medium", "topic": "equations"}}
```

Инструмент вернул `eq-m1`: «Реши уравнение 3x - 5 = 10».
Тема сохранилась из истории, сложность повысилась, решение не показано.
В обоих случаях вызов подтверждён tool-call и ответом инструмента,
а условия совпали с исходным набором.

Проверено через реальную модель `gpt-6-luna`. Пройдено 3 локальных теста:
инструмент не возвращает ключ ответа, уровень меняет упражнение в рамках
темы, неизвестные параметры не приводят к выдумыванию задачи.

## Вывод

Фреймворки помогают связать модель, данные, инструменты и состояние,
но не заменяют методику преподавания и проверку учебных материалов.
Для проекта полезны контролируемые пайплайны Haystack и явная учебная
логика. Агентный эксперимент показал, как модель выбирает собственный
инструмент и учитывает контекст при уточнении сложности.
